# Reproducing the work

The program runs from an editable checkout. Historical reproduction needs frozen study records as well as source.

## Required records

To recalculate scores, keep original gold fields, predictions, invalid/missing states, condition/repeat/pool identities, rosters, supported labels, paired masks, clusters, averaging rules and bootstrap settings. A live model is unnecessary.

To repeat generation or training, also keep corpus releases and terms, prepared memberships, exact messages, model/tokenizer identities, fitting/decoding settings and model access. A hosted alias alone does not identify immutable historical weights.

Preserve own-valid versus shared-valid populations, inner voting versus outer repeats, source uptake versus transfer, and observed-empty versus missing annotations. The prototype scorer does not replace the study-specific analyses.

## Source versions

[Source changes](source-changes.json) lists original and cleaned hashes. Shorter comments and asset-path changes alter source identity. Historical protocols and results retain their recorded IDs and hashes. Include original bound sources in the examiner archive when exact verification needs them.

The default example renderer now includes legal annotations and omits an unannotated hate field, matching the corrected renderer used in final studies. The earlier renderer remains available for its legacy control. The prompt template, labels and guidance text are preserved.

Parsing defaults, bounded repairs, strict-majority voting, lower-median severity, corpus mappings and sampling calculations are retained. Repeated labels retain their original vote-counting behaviour.

The public CLI saves new prediction files. Study-specific batch interfaces use their frozen plans and messages. Historical comparisons use their saved plans and messages; current defaults do not describe every experiment.

## Verification

Offline tests exercise mock classification outside the checkout, JSONL inputs, prompt annotations, local source mappings, read-only SQLite access, seeded partitions and index ingestion with a test backend. Missing-input tests skip explicitly. Full empirical replay depends on the separate archives.

## Knowledge-selection analyses

[Knowledge-selection notes](knowledge.md) map the SQ1 code to its required records. The included guideline matrix can be scored directly with the original template bootstrap. The cleaned code preserves study masks, repeat/pool weights, label support, resampling settings and historical identifiers. File and source-inventory changes are recorded separately.

The final micro-F1 reader correction is integrated into one module. It reads the saved ordered cluster-row lists and verifies the original pick stream. Cached retrieval accepts an existing encoder and collection, retaining selection while avoiding runtime code patching. Archive-dependent constants are loaded when an analysis uses them.

## Feedback analyses

[Feedback studies](feedback.md) maps the SQ3 code and its input requirements. Source uptake, different-text transfer, simulated labels, human judgements and classifier refits remain distinct. Saved source assignments, all four rounds, guide orders, response slots and original form IDs are needed alongside the prediction and gold records. The current source map distinguishes cleaned code from the historical bound source versions.
